# DMA runner review gate

The new `tools/run-dma-6k60.py` and `tools/dma-6k60-guest.ps1` were executed by the root operator as motion4; task exit was 0, native_drained=true, normal task Running, and normal wrapper unchanged. See [analysis](evidence/6k60-20261008/dma-production-motion4/analysis.json). Subsequent cleanup wording changes were not part of that run.

This run uses authorized administrative downtime to switch away from the normal Windows task. `platform/windows-reverse/fusion_launcher.cpp` uses `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`; therefore `Stop-ScheduledTask` is explicitly recorded as forced job teardown, not graceful GPU drain. Before stopping, the runner identifies the exact wrapper command and its descendant process tree and retains process handles. After stopping it waits up to 20 seconds for those original processes to exit. If any remain, it records normal-stop-blocked.json, starts no test writer, does not reset shared memory, and withholds normal restart. Writer mutex protection remains unchanged. This administrative switch is distinct from ordinary focus changes, congestion, or frame deadline misses, which must not terminate sessions.

For its own standalone temporary task, the guest script snapshots native child process handles of its exact peer PID. Cleanup terminates only that peer process, closing the native stdin pipe. `main.cpp` input_loop observes EOF and sets running=false, allowing normal destruction and GPU drain. Native processes are never force-terminated. A 20-second operation watchdog records outstanding native PIDs in drain-blocked.json and leaves shared memory untouched; normal restart is withheld. The GUI launcher subsequently closes its kill-on-close job when this wrapper exits, so these processes are NOT retained: forced termination is expected and must not be described as a successful drain. This is an operational failure report, not a frame-latency cutoff. This behavior remains untested on hardware.

The initial child snapshot is supplemented immediately before peer shutdown. Review exact executable identity and peer child topology on the real system before execution. The temporary task uses the GUI kill-on-close supervisor to avoid terminal windows. Let guest finally attempt peer-only EOF cleanup first. After a drain failure, wait for the temporary scheduled task to become non-running, then verify all outstanding native PIDs in drain-blocked.json have exited. A task terminal state alone is insufficient: the original process handles or PID plus original StartTime from owned-native.json must establish exit. If an original process still exists, do not start normal and do not reset SHM. Once all original processes are gone, restore normal only if before.json says normal_running=true, and read back its task state. Preserve the run failure and forced-job-cleanup classification even if service restoration succeeds. The host runner now calls tools/dma-6k60-recover.ps1 after temporary-task termination. It requires original PID plus UTC StartTime ticks for normal and native processes, including every drain-blocked PID, before restoring normal. Missing identity evidence or a still-live original process records host-recovery.json status=blocked. PID reuse is distinguished by the start-time identity. This new recovery code is not yet live-tested.

Other review points: motion4 uses a fixture gate: initialize transparently, connect the new peer, confirm initial 6K capture, then begin the 20-second motion loop; startup is excluded. Actual loop-start QPC was not logged, so analysis uses the host gate timestamp as an explicitly approximate boundary; no stamp pixels are read; sampled WGC-to-Wayland timestamps are joined through source PTS; calibration uncertainty and end-clock drift must be reviewed. Fixture submission FPS and Wayland presentation are separate metrics. Actual 6K output must be established from client and monitor geometry. Current renderer trace samples feedback rather than logging every presentation, so it is not a full displayed-frame count.

The runner accepts `--in-flight {1,2}` (default 1), records it in parameters.json, and passes it only to the temporary guest process environment as VIEWFLOW_SHM_D12_IN_FLIGHT. It never changes the normal wrapper. Python compile and CLI parsing passed; no local PowerShell interpreter was available for parser validation.
