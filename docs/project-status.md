# 当前项目进度

## 2026-09-07 最新指导原则与调整

[安全与可用性原则](security-and-availability-policy.md)现为全项目依据：不得比用户指定的 Windows remote window、Sunshine/Moonlight 施加更严格的安全限制。33ms/两个刷新周期只是性能目标，不是安全边界或退出条件。旧记录中的强制时限描述是历史实现，不再代表设计要求。

本次已修改：原生呈现开始后允许完成并报告迟到提交；接收端接受该提交并继续参考帧链；发送与呈现的进行中操作使用独立的无响应看门狗；未开始的过期画面仍可干净丢弃；等待画面和源端暂时无新帧不再导致退出；画面年龄不再按33ms撤销输入权限；无按键/按钮占用的普通悬停允许下一次移动重新进入目标，不因compositor指针焦点变化终止。

这不是全项目限制清理完成：输入事件自身及恢复握手仍有旧的短期限与终止传播路径，需要继续按新原则整改。当前构建与用户手动运行证据见[增量记录](evidence/desktop-main-input-20260906.md)末尾。实机输入仍由用户本人测试。

更新：2026-09-06。按用户要求优先完成 Linux → Windows；macOS 实机验证暂缓。完整产品目标仍以 [架构](architecture.md)和[验收表](integration-acceptance-gates.md)为准，不能将本页的有限实机结果视为整个项目完成。

## 输入法归属（用户明确要求）

输入法属于应用所在系统：Linux 应用显示在 Windows 时仍由 Linux 输入法处理；Windows 应用显示在 Linux 时仍由 Windows 输入法处理。跨端只传物理按键，不传另一端生成的组合文字。代理窗口不应启动观看端输入法，也不应截走源端输入法切换组合键。源端预编辑、候选框和最终文字属于应用画面的组成部分。

主桌面的原生 Wayland 输入法抓取路径此前仍被拒绝；现已接入精确目标的源端输入法按键与返回路径，以及候选框显示和主窗口范围内的点击，并部署等待用户手动验收。先前私有 Qt/Fcitx 模块试验的成功不能替代此路径的验收。

## 主桌面试用补充（2026-09-06 晚间）

用户已要求在主桌面启动。用户确认 Windows 实际为 3840×2400、scale 2，交互会话读回也确认为 192 DPI。已将两端配置和 owned HEADLESS-6 改为物理 3840×2400、scale 2、逻辑位置 (3072,390)，同时邻接 DP-4 右侧和 HEADLESS-1 上侧；独立编码 atlas 暂为 2048×2048。此前沿用 1536×1152/1.5 的试验配置造成尺寸与位置错误。

Dolphin 试用暴露并修复：首次时钟探测在编码热身前过期；启动立即接管本地鼠标；后台工作区/平铺越界窗口误接纳；新增窗口占满 atlas 后终止整组。现在原生输入等待接收端明确选择，动态发现只接纳当前可见工作区的浮动窗口，超容量新候选在接纳前停止。

用户随后明确确认能够看到 Dolphin，但反馈旧配置尺寸位置错误、blur 缺失、希望使用 Win+拖动。一次主桌面运行达到 2330 次 Windows 原生视觉提交，随后遇到 NVENC 超时退出。恢复修复后的另一次运行达到 9287 次提交、25 次干净丢帧，后因窗口变大超出 atlas 容量退出。这不是物理呈现或用户操作成功证明。已新增独立的编码后清理成功恢复结果，丢弃迟到包并强制下一帧 IDR/透明度引用重建；原生 GPU 六项测试通过，其中故障注入验证清理结果及下一帧 IDR。仍出现 Windows 首帧视觉变更后超过期限导致退出，尚未解决。

Linux 物理鼠标跨到 Windows 已接入同一认证会话，按实际 3840×2400、2 倍缩放处理全局坐标。独立测试鼠标完成一次进入、Windows applied ACK、移动、返回 Linux 的实机往返；随后真实连续输入暴露时钟期限映射导致拒绝的可复现路径，发送端现预留 5.5ms 时钟误差与漂移裕量，接收端限制未放宽。修复后尚未完成持续混合输入验收：实机运行仍出现呈现确认超时，以及 282 次视觉提交后原生 pointer 队列不可用。不能据此宣称稳定可用。

已合入 Windows Win+拖动状态处理、DWM blur 绑定与代理隐藏/复用，以及源端超出 atlas 容量的已接纳窗口安全暂停。超量窗口会暂时隐藏，缩小后恢复；未实现 atlas 动态扩容。Windows 25 项原生测试通过；blur 已在独立 Windows 实际 atlas 路径通过图像对比，透明边角与不透明前景保持不变，半透明区背景对比度下降约一半。Win 拖动的最新主桌面端到端验证仍待输入恢复修复后执行。

## 本轮实现

- 显示器配置统一为物理分辨率、常规缩放倍数和全局逻辑坐标。支持负坐标、错位和间隙，拒绝重叠；源端和接收端使用同一个副屏矩形。旧的边缘/百分比和逆比例配置不再进入桌面启动链路。见 [配置说明](display-layout.md)。
- Windows 代理在源窗口返回本地时隐藏并保留，再进入时复用；只有位置或大小改变时才调用窗口布局接口。
- Hyprland 移动包含工作区归属变更。松手返回时窗口完整落在本地矩形内；取消/退出尝试恢复原状态。
- 修复视频发送完成时取消正在处理的原生命令的竞态。已接纳操作必须完成记账和回复，不能因为一个视频帧完成而丢失 token 或序号。
- 移窗 IPC 使用实际已核验对端身份的连接，去掉不必要的磁盘持久化等待。私有文件权限、进程身份、单次期限和顺序检查保留。
- 桌面原生命令由独立工作线程处理，避免等待 GPU owner；停止时完成在途命令并释放 token。修复原生命令失败后的序号清理，测试覆盖媒体 owner 阻塞和上一命令可能未送达的情况。
- Windows atlas 接入已有的受限原生管道创建逻辑，设置 256 KiB 缓冲，降低默认小缓冲带来的分片等待；呈现期限、部分写入超时退出、未绑定过期证明均不变。
- 修复初始/动态窗口 ID 不一致、重复原生地址接纳和捕获停止未确认时吞掉错误。启动器校验虚拟输出实际尺寸，拒绝零尺寸输出并清理自建资源。
- Linux 本地 IPC 身份查询集中化，并补充 macOS 内核身份实现；这不是 macOS 视频后端完成的证明。
