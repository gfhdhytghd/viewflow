# 多窗口活动优先调度

每条连接独立记录实际交互和激活历史。点击、按键、滚动、拖动和完整触控手势参与排序；悬停、普通指针移动不参与。按键、按钮或手势持续期间保留交互状态，释放后延续 500 ms。未聚焦窗口的滚动临时取得优先级，不替换最后激活记录。窗口退出共享后，从仍有效的历史中回退。调度观察器不产生输入、焦点操作或输入授权。

## 媒体通道

支持新能力的连接使用后台通道 0 和优先通道 1。编码、网络队列、解码器和原生交付确认分别保持独立的有界状态。优先通道提交不等待后台解码确认；已提交的工作正常完成。接收端通过全局窗口成员列表保留另一通道的代理，通过迁移代次拒绝旧画面覆盖新画面。

- Windows 源端分开维护编码器、透明度处理、待输出帧和刷新预算。CPU 透明度压缩也按通道独立运行。
- macOS 源端各通道分别拥有准备和编码完成队列；应用宿主汇总源进程报告，协调后台刷新预算。
- Linux 源端只收集所选通道中已就绪的采集帧。GPU 读取完成后立即归还采集接收器，不等待上一帧网络确认。后台保留稳定分配，优先图集单独分配和扩容。稀疏编码沿用源窗口的固定像素位置，保留透明度分类、遮挡剔除和可选预合成；旧连接仍使用压紧布局。
- Linux → Windows 的 atlas 管道同时保留两个原生交付事务，确认可乱序返回。恢复操作等待所有已提交事务完成后再跨过媒体边界。

未发送队列可以合并过时更新；如果移除了预测参考链，会抑制后续依赖帧并请求关键帧。不会截断已经开始写出的记录。

## 拥塞和资源回退

每 250 ms 统计排队。连续三个统计窗口超过两个目标刷新周期或队列饱和时，后台上限按目标频率、30、15、5 FPS 逐级降低；持续两秒正常后逐级恢复。后台每 200 ms 至少取得一次调度机会，实际完成时间仍取决于采集、硬件和网络。静态画面继续使用既有重复帧检查。

可选编码器或图集分配失败时，保留连接并记录原因，退回单通道加权更新：优先窗口保持目标频率，后台按预算加入同一通道。接收端保留本次没有更新的窗口画面。无法继续扩大的单通道保留上一次成功的画布；超出容量的窗口保留旧画面，其他窗口继续更新。

33 ms 仍然只是性能目标。GPU 生命周期、字节流完整性和独立的操作看门狗保持各自的含义。

## 协商与配置

内部配置为 `activity_priority: auto | off`，默认 `auto`。`off` 保留原单通道行为。

原生窗口桥使用 `viewflow/1+activity/1` ALPN 协商扩展；旧连接继续使用 `viewflow/1`。扩展帧携带通道、迁移代次、优先窗口、最后激活窗口和完整成员列表，排队反馈与输入共用原来的有序控制通路。

Linux atlas 使用 `activity_priority_version = 1` 协商，原生 Windows 管道使用 VFGP v11。原生程序可明确返回 `activity=off`，协商结果降为原协议，连接不必重建。现有非恢复输入模式保持原路径；新增并行交付接在支持恢复或桌面窗口的接收模式上。

## 验证边界

自动化验证覆盖交互优先、悬停不抢占、500 ms 延续、持有和释放、窗口归属、连接状态隔离、后台服务机会、队列溢出后的参考链恢复、迁移乱序、资源回退、协议降级，以及两个原生事务在途时的恢复边界。

三端原生编译、原生协议测试、Rust 集成测试和 macOS 宿主预算测试使用隔离目录。测试中的模拟输入事件只作用于内存状态或虚拟管道，不注入真实鼠标键盘，也不改变桌面焦点。

同负载下 1、2、4、8 个窗口、后台视频和带宽受限场景仍需运行时测量。自动化正确性测试不能证明输入到画面的 p50/p95、拥塞时 p95 改善至少 25%，或无拥塞时回退不超过 5%。真实输入验收由用户操作。

部署按 Windows、macOS、Linux 源端逐步进行。发布包必须从已验收的运行版本加入活动调度改动，排除本任务之前尚未验收的正文和阴影改动；定时唤醒优化另行测量。
