# 安全与可用性指导原则

用户于 2026-09-07 明确要求：**此项目不应该拥有比 Windows remote window 和
Sunshine/Moonlight 更严格的安全限制。** 本原则适用于整个项目，优先于旧文档、
代码注释及测试中额外设定的限制；不表示现有实现已经达标。

33ms（或两个刷新周期）只用于性能目标和统计，不是安全边界，也不是退出条件。
超过目标时允许记录延迟、丢弃过时画面、完成已开始的呈现、请求关键帧或局部恢复。
不能因一次超时销毁代理窗口、断开连接，或把普通远程输入变成必须逐帧重新授权的操作。

悬停、焦点切换、本地与远端输入交接、窗口移动和短时拥塞属于正常使用。
路由失效时暂停受影响的输入、释放已持有的按键/按钮并重新建立路由；
一个窗口关闭只移除该窗口，不能使其他窗口一起消失。

保留设备配对与身份认证、正确目标和事件顺序、断线后的按键释放等常规机制。
额外限制必须有具体依据，不能单凭假设性风险或“安全起见”加入。
比较产品行为时核对对应功能和实际证据，不自行假定对照产品采用某个具体超时值。

性能目标、操作无响应的看门狗和真实连接/资源故障必须分开。
仅将33ms改为更大的硬退出数字不算完成；应验证延迟后的持续运行和恢复。
历史证据保留当时结果，不能作为继续维持旧限制的依据。

2026-10-23 已按本原则改为局部恢复（`robustness-hardening` 分支）：
coded 与 atlas 呈现错过 33ms 时迟到呈现或 REJECT 并请求关键帧，
只由 5 秒无进展看门狗或真实子进程/管道/连接故障结束；按钮、滚轮、键盘、
拖动结束按序迟到投递，不再依赖捕获新鲜度；焦点变化、租约到期、
会话锁定等撤权只暂停该窗口路由并释放按键，等待新授权恢复；
恢复握手失败只放弃该窗口的本次尝试，原生呈现进程对焦点不在、
按键未释放、目标已关闭回复 `atlas-input-recovery-rejected-v1` 而不退出；
单个坏控制消息、坏数据报、单窗口捕获失败或入组失败只影响该消息或该窗口。

仍待改项（实现差距，不是本原则的例外）：
- atlas 源端输入任务结束仍会结束串流：该任务独占连接唯一的控制读取端，
  重启需要对端协议配合。
- coded 路径 Windows 呈现进程 stdout 中迟到的原生按钮期限仍使呈现失败。
- 桌面几何确认失败仍使呈现管道失效；没有授权来源的路由（`serve()` 固定路由）
  撤权后仍退役，由所有者重建。
- 以上 Windows/macOS 专属路径尚未在本机编译，也未经实机验证。

## 桌面跨屏输入（2026-09-07）

Atlas 桌面输入按同一可靠控制流的顺序执行。普通移动、滚轮、按钮和键盘事件
不发送或等待逐事件 InputAppliedAck；队列合并仅限同一控制权下相邻的移动，
不会跨过按钮、键盘、滚轮或控制权切换。点击和滚轮之前先按顺序发送最新位置，
无需为这个位置额外等待网络往返。

这条输入路径不依赖逐事件时钟同步或捕获期限来决定能否执行，保留控制权代次、
目标设备和递增序号校验。控制权撤销仍排在先前输入之后，等待接收端实际释放
按键和按钮，再完成本地交接。其他输入协议的确认行为没有由此隐式改变。

Windows 原生输入在专用 OS 线程上执行并保持输入桌面句柄的有效生命周期，
避免异步任务在线程间迁移时隐式依赖桌面关联。绝对位置直接设置系统光标，
随后按序处理按钮、滚轮和键盘。这个本地调用完成不引入网络逐事件回执。

2026-09-07 实机定位到 Windows 前台 `Au_` 安装程序处于提升权限状态，而
接收端为普通权限。坐标已收到但系统光标未移动；将交互会话启动任务
`ViewflowMain-Active` 的 RunLevel 改为 Highest 后，请求坐标与系统实际光标
位置一致。原启动任务 XML 已备份在部署目录的
`main-task-before-input-elevation.xml`，Deskflow 服务及客户端已恢复。
这是 Windows 输入权限边界；不应把它误报成 QUIC 断连或窗口新鲜度失效。
普通权限部署无法保证操作更高权限窗口；完整桌面控制部署须具备对应的
Windows 输入权限。参见 [Microsoft SendInput 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)。
