# Sparse tile splitting during/after native move

User reported intermittent split tiles during/after moving a Linux proxy on Windows. Shape clarification was requested (misaligned blocks, narrow seams, or stale regions), with no reply received before the change. No screen capture of the reported artifact was available. Treat the rendering fix below as a concrete buffer-lifetime correction, not verified elimination of every visual artifact.

The foreground atlas used the previously bound drawing surface as the next back buffer immediately after queuing a brush swap. Moving windows changes sparse packing and source rectangles, so overwriting a surface still associated with a preceding composition generation can mix new atlas pixels with older crop coordinates. Updated production stage_gpu_surface to reuse a retired surface only after its associated RequestCommitAsync action completes. Otherwise it allocates an unbound candidate; no UI-thread wait or per-window full-size sparse backing was added. Shared-atlas retirement is requested after all proxy updates and visibility cleanup. Ordinary non-sparse swaps also associate retired buffers with a commit action.

The native test includes the production upload implementation and supplies a deliberately pending commit action: pending/missing retirement proof must select a different drawing surface, while completed retirement permits reuse. It creates GPU resources and composition objects only; no window, capture, focus operation, or input injection. It passed in the interactive Windows session. The first SSH/session-0 execution failed with E_ACCESSDENIED while constructing the compositor; as with the existing sparse GPU oracle, the new target is run explicitly in the desktop session rather than registered as a general CTest. All 35 regular CTests passed.
