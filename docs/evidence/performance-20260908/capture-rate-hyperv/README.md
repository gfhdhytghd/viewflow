# Hyper-V 开启后的 60 / 90 Hz 捕获对照

完整毛玻璃、实际 HDMI 3840×2400 @ 60 Hz、相同源和接收器二进制，只修改源配置的捕获 fps。**90 Hz 未稳定改善完整链路，默认保持 60 Hz。** 接收端始终为普通输出路径，直接绘制和背景缓存关闭。

| 捕获 Hz / 轮次 | 原生提交/秒 | 不同标记/完整 30 秒 | 绘制前→桌面中位 / P95 ms | 最大 ms | 捕获计时唯一配对/不同标记 |
|---|---:|---:|---:|---:|---:|
| 60 / rate-v1-60-a1 | 58.57 | 58.23 | 55.34 / 56.34 | 72.23 | 1747 / 1747 |
| 90 / rate-v1-90-b1 | 87.60 | 31.93 | 29.79 / 47.23 | 64.74 | 94 / 958 |
| 90 / rate-v1-90-b2 | 87.32 | 57.03 | 40.34 / 41.85 | 60.25 | 849 / 1711 |
| 60 / rate-v1-60-a2 | 57.79 | 53.90 | 29.73 / 31.29 | 711.64 | 1616 / 1617 |

90 Hz 的两轮普通路径分别提交约 87.6 / 87.3 次/秒，但桌面不同画面的观测率并未同步提高。第一轮只有 94 / 958 个不同标记能与捕获唯一配对；重复捕获的标记不用于捕获计时。完整绘制前→桌面按 fixture 帧身份统计全部所见不同标记，可比较整段延迟。60 Hz 前后两轮本身也有明显相位与长尾差异，最后一轮中位 29.73 ms、P95 31.29 ms，但最大 711.64 ms，不能宣布两帧内达标。

各轮采集标记全有效；source 均按计划 55 秒退出、观察器运行 30 秒。终点为 DXGI 所见桌面 LastPresentTime，加跨机时钟不确定度上界，不是光子时间，也未验证该帧首次显示。不同标记/秒不等同于实际显示 FPS。未删掉长停顿，也未把不同轮次的最快延迟与最高更新率拼成同一成绩。

每轮 ESRV 均未运行；参数、GPU、源内容、完整 sigma=12 背景和观察器相同。输入保持被动穿透，所有 `WindowFromPoint` 查询均未命中自有窗口；未注入输入或焦点操作。测试进程、计划任务和端口已清空，临时 HEADLESS-43 已删除，原监视器几何及 VDD 配置核对一致。
