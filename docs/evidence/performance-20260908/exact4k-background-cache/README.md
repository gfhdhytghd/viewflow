# 实际 4K 输出的背景缓存对照

**30 Hz、15 Hz 各两轮开启缓存都比各自前后关闭缓存的对照更慢，保持缓存默认关闭。4K60、两帧内显示仍未证明。**

本组使用实际 HDMI 3840×2400、约 60 Hz 输出，观察器要求唯一的活动 3840×2400 显示器。源内容同为 3840×2400，含边框捕获 3848×2408、atlas 3968×2432，客户端按 1:1 放置。6K 虚拟显示器仍为另一路输出，没有重置用户桌面布局。

本组复测[背景精确变化检测](../background-change-detection/README.md)的独立候选：完整背景缓存限于当前显示器，按 Hyprland radius=5、passes=4 模糊，GPU 逐像素比较全部 RGBA，相同时跳过重复模糊。关闭组使用原有实时背景。本组不修改生产默认值，也不关闭用户要求保留的背景效果。

完整结果见 [comparison.json](comparison.json)。八轮动画标记区间覆盖均超过请求时间的 99%，缓存开启轮全部为 3840×2400，变化检测为严格 RGBA 相等；没有后台构建或处理错误。原生提交均约 57–58 次/秒，而候选桌面观测均约 32–33 次不同帧/秒，不能用提交计数掩盖显示端退步。

30 Hz 两轮 commit→所见桌面中位为 40.68 / 42.21 ms，其前后关闭组为 33.02 / 37.08 ms；15 Hz 两轮为 41.18 / 42.43 ms，其前后关闭组为 36.93 / 28.94 ms。这些是各组分布的中位数，不能相加或当成逐帧差；最后一段包含排队、GPU、DWM 与观察端点，不是 DWM CPU 时间。

30 Hz 重复模糊跳过比例约 78%–82%，15 Hz 约 86%–89%。捕获矩形缩小到 4K 后仍未带来整链路收益；本组没有分别消融捕获、比较与合成，不能把退步单独归因于某一个子阶段。不同轮次背景变化量也不同，不把候选刷新频率当作精确的屏幕背景显示率。

代码核对排除了一个重复优化方向：`atlas-sparse-opacity` 中 589 个 patch / 184 个非 opaque patch 是合并前的协议统计；`stage_sparse_visuals` 已调用 `CoalesceSparsePatches`，不能把它们当成实际合成节点数。背景缓存的 `MinUpdateInterval` 当前为 0，但这些累计计数不足以证明捕获过快是瓶颈；本组没有修改该属性。

所有原始时钟、配帧、重复 marker 歧义与长尾均保留。分析器只用唯一源 marker 对应的捕获帧计算捕获阶段延迟，未填补歧义配对。

## 方法与范围

先运行 30 Hz 的 off/on/on/off 对照，若未获得收益，再运行 15 Hz 对照。全部运行使用同一个原生接收器、同一个支持 30/15 Hz 的启动器、相同 Rust receiver、Linux 源端、动画程序与 exact4k 观察器，每轮核对实际二进制 SHA256。源端持续 55 秒，桌面观察 30 秒。每两秒检查图案进程、可见工作区与动画日志是否持续更新；显示尺寸变化会使测量失败，不作为会话退出策略。

原生提交次数不等于屏幕刷新次数。桌面不同帧数统一除以完整请求的 30 秒，Desktop Duplication 仍可能漏掉中间帧。所见桌面的 LastPresentTime 不保证对应 marker 的第一次呈现，更不是光子时刻；延迟含时钟不确定度。因此这些结果用于同条件候选比较，不足以宣布实际 60 fps、33.3 ms 内达标。

没有注入输入或主动改变用户窗口焦点。测试只创建并清理自己的非激活窗口、计划任务和 Linux headless output；用户自行切换焦点不视为测试注入。保持生产 ESRV 进程原有优先级。每轮保存完整时钟映射、逐帧身份、观察器几何、后台统计和清理状态。

运行与分析工具位于 method，原始日志压缩保存于 runs。测试依赖已有私有配对配置；归档不含密钥、运行配置或二进制。原生候选的完整源代码、构建与像素验证继承[既有实验归档](../background-change-detection/README.md)，本组没有重新执行图像正确性 oracle。每轮已测二进制身份保存于 state.json，可核对其对应关系。

前后只读探针均确认 HDMI 3840×2400 主屏与左侧 6K 虚拟输出：[开始](method/display-cache-probe-before.log)、[结束](method/display-cache-probe-after.log)。两个临时 Linux 输出 HEADLESS-31 / HEADLESS-32 均已移除；自己的 Windows 测试任务、进程与 UDP 49073 均已清理。虚拟显示驱动 XML 与原有 SHA256 一致，未运行显示模式修改。ESRV PID 10132 前后保持 High。[最终状态](method/final-state.json)
