# 严格 4K 屏幕基准

按照用户要求，后续性能结论以实际 3840×2400、约 60 Hz 的 HDMI 输出为基准。观察器新增 `exact4k`：只选择唯一的 3840×2400 活动输出，不再将 6144×3456 作为“支持 4K”的替代；运行中输出尺寸变化会使本次测量失败。这是测量工具的校验，不改变 Viewflow 会话的可用性规则。

两轮完整动态复测均确认目标是 Intel GPU 的 HDMI 4K 输出，源内容也为 3840×2400，按 1:1 放置。此前的 6K 数据保留为历史对照，不能当作同一显示配置下的 4K A/B。**目前仍未证明 4K60、两帧内显示。**

## 当前显示状态与切换原因

第一次读取活动路径时，Windows 只激活了 MTT 虚拟输出，源尺寸和信号均为 6144×3456。其配置文件只列出这一种模式；驱动概要中同时出现的 Intel 3840×2400 不能证明当时的活动桌面就是 4K。[原配置](method/vdd-before.xml)

检测期间 HDMI 输出重新出现并成为主屏：`DISPLAY1` 为 0,0,3840,2400，180° 旋转，实际信号 3840×2400，刷新分数 58679000/978000（约 59.999 Hz）；6K 虚拟输出位于其左侧。活动路径回读保存于[显示探针](method/display-probe.log)。没有证据确定这次变化由 KVM 的哪项行为触发，也没有把 HDMI 回归归功于本次程序。

曾准备向虚拟驱动配置补入 4K。执行尝试中设备标识的字符串替换有误；模式工具随后发现活动输出已经变成两路，在调用显示模式修改 API 前退出。原 XML 已恢复并以 SHA256 核对，后续直接选择重新出现的 HDMI 输出，未再次执行模式修改。[模式工具退出记录](method/first-set-4k.log)、[恢复核对](method/first-recovery-state.json)、[最终配置和清理状态](method/final-state.json)。相关设置脚本属于已放弃的准备过程，不是本基准的复现入口。

只读探针的早期两次尝试分别遇到任务启动状态读取过早和 CRT 对零长度日志缓冲的异常；修改等待逻辑与缓冲长度后成功。失败状态原样保留，未把它们计入性能结果。

## 两轮结果

运行正常 H.264/mTLS 链路，背景缓存关闭，保留现有完整毛玻璃。源内容 3840×2400，捕获含边框为 3848×2408，atlas 3968×2432。像素帧标记、帧身份和时钟映射核对通过，观察器没有无效 marker 或遗弃读回。每轮观察 30 秒，图案持续更新，标记区间覆盖超过 99%。

[完整统计](comparison.json)与逐轮原始压缩日志保存于 runs。两轮原生接收器、Rust receiver、Linux 源端/图案程序和新观察器的哈希一致。原生使用前一阶段的独立构建，缓存与变化检测均关闭，其[源代码和构建身份](../background-change-detection/README.md)可追溯；观察器本阶段独立构建，哈希见[observer-hash.json](method/observer-hash.json)。

第一轮阶段数据中，编码 host 中位约 6.89 ms，编码后到 pipe admission 约 2.73 ms，解码约 1.49 ms，visual bind/commit host 约 0.057 ms；commit 到所见桌面中位约 35.74 ms。最后一段包含排队、GPU、DWM 和观察端点，不能称为 DWM CPU 时间，也不能直接把不同集合的阶段中位数相加。它支持继续定位提交后的路径，尚未隔离具体责任阶段。

原生提交数不是屏幕刷新数。Desktop Duplication 可漏观中间帧，LastPresentTime 也不保证对应某个 marker 的首次呈现，更不等于光子时间。表内延迟是含时钟不确定度的所见桌面上界，未以此宣布目标达成。6K 虚拟屏仍作为另一路输出存在，未通过重置整个桌面布局来制造基准。

## 复现与清理

[build-observer.py](method/build-observer.py)构建独立观察器；[run-integrated-ab.py](method/run-integrated-ab.py)只运行两轮关闭缓存的基线，内部使用 `exact4k timer1`。复现需更新路径和真实二进制哈希，并确保实际 4K 输出保持活动。4K 消失或尺寸变化时将该次数据判为无效，不自动选择 6K。窗口和输出由测试创建，没有输入或焦点注入。

Linux 临时 HEADLESS-30 已移除，自己的 Windows 任务、窗口与进程已清理，49073 端口已释放，虚拟驱动配置哈希回到原值。所有无关显示器和插件保留；未修改生产遥测进程的优先级。

运行 `PYTHONDONTWRITEBYTECODE=1 python docs/evidence/performance-20260908/display-4k-baseline/method/verify-archive.py` 可离线解压并重算两轮统计和时间线，核对 4K 尺寸、完整动态观测、运行身份、清理与全部归档哈希。配对配置、密钥与可执行文件不在归档中。

MTT 驱动的配置方式参考[项目官方文档](https://github.com/VirtualDrivers/Virtual-Display-Driver/wiki/How-to-configure-the-driver)；本阶段关于具体模式、活动路径和回退状态的判断以本机读取结果为准。
