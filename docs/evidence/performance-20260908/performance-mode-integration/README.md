# 两档性能模式接线与真实 4K 复测

源配置新增 `performance_mode: "frame-rate" | "latency"`。默认保持帧率优先的共同固定捕获节奏；延迟优先选择提交唤醒并保留静态补采。字段从初始源配置传到初始窗口和后续自动加入窗口的捕获启动，不修改图像、显示几何、认证、输入或故障恢复。

**真实 Rust 源端读取两种配置后，已按 stream ID 与捕获插件的 grid / commit 日志逐一对应。私有 shim 只改插件命名空间，不决定模式。四轮完成，但完整链路延迟收益仍不稳定，默认不改为 latency，当前生产服务与界面尚未替换。**

| 模式 / 轮次 | 原生提交/秒 | 不同标记/完整30秒 | 绘制前→桌面中位 / P95 ms | 最大 ms |
|---|---:|---:|---:|---:|
| FrameRate / modes-v1-grid-a1 | 58.06 | 57.40 | 37.12 / 38.53 | 122.38 |
| Latency / modes-v1-commit-b1 | 57.56 | 55.20 | 28.26 / 29.64 | 283.16 |
| Latency / modes-v1-commit-b2 | 57.55 | 57.30 | 39.98 / 40.92 | 106.93 |
| FrameRate / modes-v1-grid-a2 | 57.79 | 56.53 | 34.10 / 35.33 | 118.11 |

第一轮 Latency 中位和 P95 比两轮 FrameRate 更低，但第二轮 Latency 中位与 P95 均更高；仍有 106–283 ms 的长尾。不能用第一轮 28.26 ms 宣布模式稳定达到两帧内，也不能拼接不同轮次的最高吞吐和最低延迟。4K60 / 两帧内显示尚未证明。

四轮保持实际 HDMI 3840×2400 @ 60 Hz、相同 H.264 和完整 sigma=12 毛玻璃、相同 Windows 接收二进制；源端为本轮新构建的 Linux release 程序。源运行 55 秒，观察 30 秒，所有采集标记有效。DD LastPresentTime 是所见桌面更新时间，不是物理光子或已证明的首次显示；不同标记/秒不等同于实际显示 FPS。逐帧排除、唯一配对、时钟不确定度及长尾保存在 [comparison.json](comparison.json)。

## 配置、工具与验证

- 既有配置省略字段时继续 FrameRate；序列化往返、非法选项、Latency 与不支持的 HyprCapture 后端组合校验通过。
- 捕获入口选择与共享 stop / 清理入口测试通过；GPU feature 编译检查和完整 release 构建通过。
- 同一调度源码的 8 项 CTest 通过。真实 GPU smoke 169 帧验证 wire、双 FD、fence、持有帧不复用、组内成员停止与同 ID 重建。
- `tools/viewflow-performance.py` 从 systemd 的结构化有效启动参数读取配置与 peer，先校验后写入；配置写入为原子操作，失败恢复原配置。8 项事务测试通过，包含有效二进制不匹配与重启失败恢复。
- 两个互斥按钮的 Quickshell 组件通过 `qmllint`，包装脚本语法通过。未通过模拟点击来宣称实际界面验收。

实际自动加入窗口会沿用同一配置字段；本轮全链路试验使用初始静态选窗，未独立重跑真实桌面自动加入流程。已有自动启动配置测试通过。源代码改动、Git 基线及构建输入哈希保存在 `source-changes/` 和 `method/`；四轮源、接收、插件及观察器身份均有记录。

四轮 ESRV 均为 PID 8628、High（128），本测试未修改它。嵌套 Wayland 合成器只开放 render / NVIDIA 设备，无物理输入或 seat；自有输出远离全部现有显示区域。Linux fixture 空输入区域、Windows 测试窗口鼠标穿透且不激活；未注入输入。退出后嵌套与自有输出清理、原显示几何/插件不变、Windows 诊断进程/任务/端口清空，VDD 配置一致。

`python method/verify-archive.py` 可从压缩日志复算，关联源端所选模式与原生实际入口，核对帧标记、GPU smoke、二进制与源哈希和清理。[使用方式](../../../performance-modes.md)。这项接线提供两档选择，不构成已部署或性能达标声明。
