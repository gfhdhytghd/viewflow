# 提交唤醒捕获：首版隔离对照

实际 4K 60 Hz、完整毛玻璃、独立嵌套 Hyprland 的 grid / commit / commit / grid 四轮。候选由主 surface 内容提交触发延后捕获，合并密集通知，限制到请求帧率的两倍；静态补采维持请求帧率。**候选降低部分采集前等待，但全链路延迟及观测更新率仍有明显轮间变化，尚未采用为默认。**

| 轮次 | 原生提交/秒 | 不同标记/完整30秒 | 绘制前→桌面中位 / P95 ms | 最大 ms | 绘制前→捕获中位 ms |
|---|---:|---:|---:|---:|---:|
| wakeup-v1-grid-a1 | 58.37 | 57.80 | 46.58 / 47.71 | 63.48 | 15.78 |
| wakeup-v1-commit-b1 | 70.71 | 45.80 | 26.53 / 44.08 | 78.58 | 0.47 |
| wakeup-v1-commit-b2 | 65.47 | 56.50 | 39.88 / 41.09 | 57.62 | 0.46 |
| wakeup-v1-grid-a2 | 58.29 | 57.90 | 37.40 / 50.35 | 53.41 | 2.99 |

候选两轮捕获尝试为 4040 / 3723，其中提交触发 3278 / 3281、定时补采 762 / 442。原生提交约 70.7 / 65.5 次/秒，超过新内容频率；桌面所见更新未达到 60。下一候选将只调整新内容之后的首次补采时刻，验证减少重复捕获是否改善完整链路。

各轮均为 55 秒源端、30 秒桌面观察，所有采集标记有效。四轮开始前 ESRV 已自行重新出现，PID 8628、优先级 High（128）在各轮前后相同；测试没有停止或修改该进程。此前直接在主桌面的捕获频率对照期间 ESRV 为空，因此不能把跨实验变化只归因于采集策略。计时终点为 DXGI LastPresentTime，加跨机时钟不确定度；不是光子时间，未证明首次显示，观测不同帧数也不能替代实际显示 FPS。捕获相关阶段只使用唯一捕获配对，全部所见不同标记的绘制前→桌面统计保留于 [comparison.json](comparison.json)。不能拼接不同轮的最好吞吐与延迟；4K60、两帧内仍未证明。

## 实现与验证

相对 [前次相位跟随原型](../capture-phase-follow/README.md)，仅改动 `capture_commit_schedule.hpp` 和其策略测试；原 renderer、cohort 和 HCGR GPU 生命周期不变。通知不在回调内进入 renderer，而是唤醒单一 timer，不积累帧队列。最大两倍请求率是候选性能调度，并非连接、输入或授权限制。

Release 构建与 8 项 CTest 通过。测试覆盖迟到定时器不累积漂移、早晚提交、通知合并、速率限制、长停顿、恢复和整数饱和。嵌套实际 GPU smoke 验证 169 帧的 wire、双 FD、native fence 和身份；持有 A 时 B 可继续，停止 A 不影响 B，空 cohort 可同 ID 重建。此 smoke 不替代像素证据；完整流 marker 均有效，毛玻璃路径使用 [前组相同接收二进制和像素验证](../hyperv-timer-enabled/README.md)。

嵌套合成器位于相对全部已有输出 X/Y 均相隔至少 32768 像素的自有 HEADLESS-44，bwrap 只开放 render / NVIDIA 设备，不提供物理输入或 seat / DRM 节点；fixture 使用空输入区域，Windows 测试窗口鼠标穿透、不激活。未注入输入。当前桌面插件未更换，退出后嵌套进程和自有输出已移除，原输出几何和插件列表核对一致，Windows 诊断进程/任务/端口清空，VDD 配置不变。

`python method/verify-archive.py` 可从压缩日志重算四轮，核对 GPU smoke、源身份、二进制身份及清理。[实现差异](method/change-ledger.json)、[嵌套状态](nested/state.json)。
