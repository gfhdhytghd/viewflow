## 测量条件

Linux 隔离嵌套 compositor、3840×2400 GPU fixture、scale 2、atlas 3968×2432。Windows 要求唯一实际 3840×2400 输出，保持完整 sigma=12 host blur、普通输出路径、背景缓存与 GPU 查询关闭。Hyper-V 计时器和按需亮度读取修复保持已应用状态。每轮 source 55 秒、异步 DD observer 30 秒；帧率列用不同 marker 数除以完整请求 30 秒，未用较短 marker 跨度推高结果。

DD LastPresentTime 是包含所见 marker 的一次桌面更新时间，可能不是第一次显示；保留现有成对时钟模型的不确定度。绘制前→桌面包含捕获等待，捕获→桌面另列在 JSON。原生提交速率及 DD 观察更新率均不能替代已验证的物理 FPS。

四轮无效画面 marker 均为 0，readback abandoned=0。第二轮提交唤醒有一个重复捕获 marker，只从要求唯一捕获身份的分段统计排除，完整绘制前→桌面集合保留。169 帧双流 smoke 验证持有 A 的帧时 B 继续前进、停止一流不损坏另一流、空组重启及旧固定节奏入口。测试窗口保持鼠标穿透／空输入区域、不激活，没有注入输入或调用焦点切换。

测量期间没有编译或并发运行其他测试。下一项共享 blur 实验的源码在此期间离线准备，Windows 构建在本批次完成并归档清理快照后才启动。

## 身份及清理

四轮 sender/fixture 身份匹配[缓存候选源码及二进制](../import-cache-hyperv-ddc/method/linux-binaries.json)，候选完整源快照和 GPU 正确性测试保存于该批次；本次复用同一个 sender，没有再次编译。Windows 原生呈现器、receiver、runner、观察器与 Hyper-V 修复后对照相同。每轮核对亮度脚本仍为 `bd402aa4…`；同一 Intel 遥测 PID 保持 High，未调整进程或线程优先级。

本批次结束时私有测量进程、任务及 49073 端口均为 0，VDD 配置哈希一致；嵌套 compositor 和自有输出已退出，原显示器几何及根插件保持一致。本批次没有替换生产 sender 或捕获插件。

运行 `python3 method/verify-archive.py` 会离线解压、复算四轮端点时间线和导入记录，检查实际模式、被动窗口、身份、清理快照及 SHA256；不会启动窗口。运行测量的脚本包含当时的私有路径，重用前需要重新核对实时身份。配对私钥及配置明文不归档。
