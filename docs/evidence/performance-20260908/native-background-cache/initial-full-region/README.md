# 完整范围采样：首轮性能回退

此轮已经使用独立采样 HWND，空间内容校验有效，不再使用失真的 16×16 裁剪。后台计算与发布移出前景线程，但开启后两次性能均更差；没有默认启用。

| 路径 | 原生提交 Hz | 桌面变化 Hz | 捕获到桌面上界中位 ms | P95 ms | 背景实际交付 Hz |
|---|---:|---:|---:|---:|---:|
| bg-off-a1 | 58.162 | 38.523 | 43.304 | 60.495 | — |
| bg30-on-b1 | 54.299 | 26.842 | 63.828 | 98.396 | 19.680 |
| bg30-on-b2 | 53.942 | 25.206 | 64.711 | 103.408 | 18.017 |
| bg-off-a2 | 58.184 | 43.300 | 45.855 | 53.932 | — |

两次开启的最后缓存范围分别为 4395×3231、5055×3456，对应移动余量 369、1029 像素；捕获内容本身为 3848×2408。启动定位造成的速度估计使缓存扩张，静止后仍未收缩。后续实现增加静止 250 ms 后回收多余移动范围；此处保留修复前数据。不能将两次不同缓存范围当作相同 GPU 工作量，也不能把后台线程存在当作性能改善。

内容为 3840×2400、scale=2，四条 128 像素半透明边缘与不透明中心；H.264、正常 mTLS、编码质量及源端不变。每轮源端 55 秒、Desktop Duplication 观察 30 秒；观察器实际输出为 Intel GPU 上的 3840×2400@60，另有一块位于左侧的 6144×3456 显示器。此版本按虚拟桌面的外接矩形分配缓存，因而越过当前显示器边界；后续按用户要求改为只缓存当前显示范围。时钟映射、帧身份、图像尺寸、观察器有效性和清理均由分析器复核。上界包含时钟不确定性，Desktop Duplication 观测不是光子测量，也不声称最早呈现时间。

原始压缩日志、全部长尾及分析保存在 [runs](runs/)，编译输入在 [source](source/)，二进制身份在 [integrated-binary-hashes.json](integrated-binary-hashes.json)。四轮关闭／开启／开启／关闭使用同一二进制，仅后台开关不同。隔离输出 HEADLESS-22 及自己的任务、窗口和进程已清理，未注入鼠标、键盘或焦点操作。
