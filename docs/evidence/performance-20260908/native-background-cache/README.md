# 原生窗口后台模糊缓存

已完成显示范围裁剪与原生接线，并保留了 30/15 Hz 性能对照。空间内容、缓存扩展、移动、缩放和透明洞已通过隔离像素测试；尚未证明 4K60、两帧内显示。实现已接入原生接收器，但默认关闭，使用 `VIEWFLOW_ATLAS_BACKGROUND_CACHE=1` 显式开启；默认背景目标为 30 Hz；只在显式设置 `VIEWFLOW_ATLAS_BACKGROUND_CACHE_HZ=15` 时使用 15 Hz。

缓存先按窗口外的 182 像素滤波范围与至少 128 像素移动余量估算，再严格裁到当前显示器边界，纹理绝不大于该显示范围；运动结束 250 ms 后，后台收缩不再需要的额外范围。窗口接近可用边界时异步准备新一代缓存；旧图按桌面坐标平移，缩放窗口不会拉伸背景。跨屏窗口的背景在显示边界分区：当前显示器内使用缓存，其他部分继续实时渲染。覆盖不足或后台失败时使用现有实时背景，保留前景与会话。

前景线程只更新合成属性、尝试读取最新发布的表面。独立工作线程创建采样窗口、D3D11 设备、着色器和几何代际，GPU 工作另在线程上执行。三个表面槽只发布 GPU 完成的结果；旧显示槽在合成提交完成后才重新使用。移动、缩放、定时器和正常前景提交都会更新缓存绑定。

## 背景来源的关键修正

此前 [16×16 裁剪实验](../background-buffer/README.md#纹理校验更正)虽然取得大尺寸纹理，实际上把一个局部颜色扩展到整张图。去掉裁剪后，放大子 Visual 仍无法扩大 HWND 对应的 HostBackdrop 区域。两种错误路径的条纹原始图分别在 [clipped-anchor](method/clipped-anchor/) 和 [unclipped-proxy](method/unclipped-proxy/)，不作为背景保真性能证据。

当前实现为每个缓存代际创建与缓存范围等大的独立采样 HWND，紧贴目标窗口下方，保留其他本地窗口在背景中的内容。根 Visual 使用 0.000001 的非零透明度保持 DWM 更新依赖，完整源 Visual 由 WGC 取图。窗口采用 `WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`，不接受激活；[Windows 窗口文档](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features)说明 layered 与 transparent 组合的鼠标穿透语义。这里只验证 API 属性及像素，没有注入真实输入进行物理验收。

HostBackdrop 本身已经处理过桌面背景，原始条纹就带有模糊。其后使用从 Hyprland 0.56.2 移植的 SDR HLSL：size=5、passes=4、contrast=0.8916、brightness=1、noise=0.0117、vibrancy=0.1696。独立 GLSL/HLSL 算法核对见[前一轮证据](../background-buffer/README.md)；不能据此声称整个 Windows 背景来源与 Hyprland 原始桌面逐像素相同，也未验证 HDR。

## 已完成的像素与几何检查

[工作线程窗口测试日志](method/native-background-result.log)验证独立本地背景由红色变成绿色后，前景半透明区域随之更新。24 条 64 像素竖条覆盖整个采样范围；窗口平移 64 像素，接着移动 192 像素并从 512×512 放大为 700×600，最后恢复初始几何，同一桌面位置读数一直为 RGB 34,41,86。包含快速移动及静止后收缩的最终测试重建八代，无构建或本地错误。

[整幅像素比较](method/worker-pixel-comparison.json)中，恢复原位置后 1132×1132 缓存图与移动前逐字节相同；原始 HostBackdrop 图最大相差 1 个 SDR 码值，平均差异 0.01395；节点使用 0/0.01 像素刷新偏移。这里比较的是移动前和最终恢复后的完整图；中间几何通过桌面采样核对，并未保留每一步完整纹理。

把中心不透明区换成完全透明洞后，现有合并逻辑将五个矩形合并为一个背景节点，缓存继续绑定；洞内仍显示原本的纯绿本地窗口，误差阈值为每通道 2。恢复不透明中心后重新得到四个背景节点。测试进程未改变前台焦点，未注入输入；自己的窗口、计划任务和进程均已清理。

MSVC Release 构建、启用 assert 的 2,688 项缓存几何测试、2,401 项显示分区覆盖/不重叠测试、稀疏矩形合并及不透明区域测试通过，见[构建记录](method/incremental-build.log)及[测试记录](method/pure-tests.log)。完整源码快照位于 [source](source/)，性能实验的原生程序及 runner 哈希见[二进制身份](method/integrated-binary-hashes.json)。


当前测试的显示范围为 6144×3456，工作区 6144×3360；右侧越界用例只创建 `[5326,122,6144,1254]` 的 818×1132 缓存，屏内读数 RGB 13,106,45，与窗口位于屏幕中间时相同。另一个纯几何用例用实际 3840×2400 显示范围与四周超出 4 像素的全屏窗口，任意测试速度都只能得到 3840×2400 缓存。

按显示器裁剪后的首次运行在红→绿阶段失败：缓存绑定消失，桌面样本为黑色，已保存[失败记录](method/display-first-failure-native-background-result.log)。增加窗口可见性诊断后重跑全部用例通过，但失败原因未确定；两次测试之间系统显示配置也从 3840×2400 变为 6144×3456。不会将失败记录计为通过或把显示配置变化直接认定为已证明的原因。

这八轮实际输出都为 Intel GPU 上的 6144×3456@60，内容仍为 3840×2400，捕获含透明边框为 3848×2408、atlas 为 3968×2432。缓存为 4238×2798，包含最初窗口位置留下的预留范围，并始终受当前显示器边界限制。前景协议、H.264 质量和正常 mTLS 配对保持不变。两组各自使用关闭／开启／开启／关闭顺序，全部使用同一原生与 runner 二进制；[身份和阶段分布](comparison.json)及[源码哈希](method/source-sha256.json)可核对。

分析检查每次桌面观察期间的显示几何一致、缓存尺寸不超过该显示器、帧 ID 与 QPC 单调、时钟映射有效、观察器无错误/未完成读回，并保留所有身份重复与不完整覆盖。原生提交频率不是物理显示频率；上界包含时钟校准不确定性，跨阶段的中位数不可相加。

[30 Hz 清理状态](method/control-state-30.json)、[15 Hz 清理状态](method/control-state-15.json)确认 HEADLESS-26/27 已移除，自己的窗口、计划任务和进程均已清理，已有显示器和插件保留，esrv_svc 的原优先级未改。没有注入鼠标、键盘或焦点操作。此前按虚拟桌面外接矩形分配的两组结果另存 [initial-full-region](initial-full-region/README.md) 与 [virtual-desktop-idle](virtual-desktop-idle/README.md)，不与不同显示配置混算。

运行 `python docs/evidence/performance-20260908/native-background-cache/method/verify-archive.py` 可离线复算八轮分析、像素差分与几何/分区测试，核验源码、二进制身份、显示边界、清理状态及文件清单；不会重新操作桌面。

15 Hz 组期间记录到 DP-4 的工作区从 5 变为 4；D2 结束时测试输出的活动工作区也从 7 变为 9。没有停帧当时的工作区采样，不能确定触发时刻或将其认定为已证明原因。后续控制器会检查自己的 fixture 是否仍在活动工作区及是否继续产生日志，失活则记录状态并中止该轮，不把静止画面作为动态性能数据，也不恢复或改变用户工作区。
