# 完整毛玻璃：独立 alpha 遮罩对照

2026-09-08。已完成 Windows 原生图像校准、正/负例以及两轮性能对照。**没有稳定性能收益，未接入产品。** 两种性能模式都完整保留实时 HostBackdrop 与四个背景节点，sigma=12，没有关闭、冻结或降低背景效果。

## 结果

| 轮次 | 遮罩来源 | 有效配帧 | 绑定→所见桌面中位 ms | P95 ms |
|---|---|---:|---:|---:|
| 正序 | 每帧彩色表面 | 522 | 15.133 | 19.909 |
| 正序 | 独立恒定 alpha | 403 | 15.354 | 20.186 |

候选正序稍慢、反序约快 0.49 ms，不能支持稳定改进。两轮各提交 1,980 帧/33 秒，没有漏过提交时隙；DD 整轮观察变化率分别为 35.207/35.295 次每秒，并非已证明的物理帧率。各段变化率单独保留在[完整统计](runs/mask-comparison.json)，不把不连续片段拼接为一条速率。

每轮在同一进程内每 240 个实际提交帧切换遮罩输入，第二轮反序；固定排除每段前 30 帧预热，最后一段覆盖不完整。3848×2408 GPU 动态前景；四个 128 像素边界区域为半透明，中心与 frame marker 为不透明，最外四像素透明。所有源 alpha 都只由坐标决定，不随帧号变化；前景颜色持续变化。候选用第三张保留的表面提供 alpha，HostBackdrop 仍随真实桌面变化。

DD 使用同机 QPC 与 LastPresentTime，终点为**观察到含该标记的桌面更新**，可能晚于首次显示，不是光子时间。这是 Windows 本地测试，不包含 Linux 捕获、编码、网络或解码，不能据此认定全链路达到 4K60 / 两帧延迟。原生探针与观察器两轮均 exit=0，ring pending_peak=2、abandoned=0；两轮前后台 HWND 都为 66730，没有注入输入或改变焦点。ESRV 服务在两轮前后均为 PID 10132 / High，TimeCritical 线程 5416、7500；没有改变优先级，快照不等于连续监控。[控制记录](runs/controls-state.json)。

## 图像正确性与发现的参考差异

初始正例使用较早的逐 patch 参考渲染器，在半尺寸加 0.25 像素偏移时出现 1,911 个 RGB 通道误差超过 2。随后关闭候选的遮罩替换，直接比较当前产品与旧参考，同一场景仍出现完全相同的 1,911 个通道差异。该校准隔离了既有路径差异，不能把它归因于遮罩复用，也不能将它隐藏为通过。[初始运行](initial-pixel-oracle/alpha-mask-positive.log)、[当前产品与旧参考校准](alpha-mask-baseline.log)。具体差异来源尚未进一步定位。

改用**当前产品**作为参考后，12 阶段全部通过，RGB 通道误差超过 2 的数量均为 0；没有记录最大通道差异，因此不宣称逐位完全相同。覆盖前景更新、后方窗口颜色变化、布局重排、alpha 128→64→192→128、缩放 1/0.75/0.5、0.25 像素偏移及恢复，只刷新四次遮罩。后方窗口的颜色变化在遮罩保留时仍有响应；三个面板全都启用模糊，以解析得到的未模糊颜色作数值对照，没有关闭模糊的面板。

故意不刷新改变后的 alpha 的负例，在第 4 阶段检出 146,688 个超差通道并以预期结果 1 退出。正例结果 0、负例结果 1、旧参考校准结果 1，都验证了准确失败阶段，不能以任意非零退出冒充有效负例。每次结束后的探针进程和任务数均为 0。[结构化图像结果](pixel-comparison.json)、[正例](alpha-mask-positive.log)、[负例](alpha-mask-stale-mask.log)。

## 实现与复现

[性能探针](../../../../tools/windows_mask_update_probe.cpp)和[图像 oracle](../../../../platform/windows-composition-preview/sparse_alpha_mask_test.cpp)均为隔离诊断，不是产品缓存实现。性能 EXE SHA256 为 `D43944326F61180A54117A64CFEA856EDE5CB874222FFB37C43D6190619A5B0C`；最终图像 oracle 为 `7229B8112DF5624B80769F711E92DDB72180E2793FC0264CD0E384DA98F618F7`。最终源在 source，原始构建、失败链接（缺少 user32.lib，后修正）、运行、分析脚本在 method。首次 oracle `CA6B...` 对旧参考的失败另存 initial-pixel-oracle，不能混作最终正例结果。

所有脚本从仓库根目录运行。`method/run-oracle.py` 支持 positive / stale-mask / baseline；先核对当前 Windows 隔离路径和已登录的交互用户。`method/controls.py` 执行两轮性能对照，`method/analyze.py` 解析日志；重现时需替换脚本中的本次主机、隔离目录及 `/tmp` 路径。原始时间日志与逐帧配对无损压缩在 runs。

Windows 在准备过程中曾重启，未登录时的任务没有实际启动，失败状态与清理记录保存在 failed-start；登录后才进行上述有效运行。没有调整系统登录方式或恢复旧进程优先级。

SourceIn 的输出只用到遮罩输入的 alpha，这支持分离输入的语义；它不保证 Windows 实际减少背景重算。[微软 Composite 效果](https://learn.microsoft.com/en-us/windows/win32/direct2d/composite)。当前结果不支持为了这一候选增加产品表面缓存；下一步转向重新测量完整的 4K 远程链路。
