# 显示器坐标布局与 Windows 往返验证

日期：2026-09-06。仅针对本轮 Linux 源窗口 → Windows 代理。macOS 测试按用户要求暂缓。

## 环境与边界

Linux 使用隔离的嵌套 Wayland Hyprland、临时运行目录和自建 Qt 输入记录窗口。两个嵌套输出为 1280×960 和 1024×768，逻辑位置分别为 0×0、1280×0。Windows 为已授权 SSH 的 WindowsVM（172.16.105.70），本机显示区域 3840×2400；每次使用独立临时目录和有限时的交互任务。输入只针对该次程序的 PID、窗口类和标题。结束后回收自建进程和任务，不加载主桌面插件、不操作现有用户应用。

配置使用物理分辨率、常规缩放倍数和全局逻辑坐标；见 [配置说明](../display-layout.md)。没有边缘百分比映射。所有既有事件、保留帧时限保持不变。

- Windows 自建代理截图已从运行 8 的独立临时目录取回并目视核对，显示完整 Qt 网格测试窗口。图片只包含本次自建代理区域。
- 运行 8 首次返回成功、第二次失败，暴露源端处理竞态：视频发送完成会取消仍在等待原生命令的策略处理。修复后已发起的处理必须完成记账和回复。回归测试让媒体先完成、原生处理后完成，确认处理没有被取消。

- 运行 14、16、18 分别验证 1 倍、1.5 倍、1.5 倍且副屏位于 `(-1024,40)` 的连续两次桌面往返。最后一种最终本地位置 `[2,72]`、大小 `[791,598]`，完全位于 1280×960 本地输出内。

## 已落地的关联修复

- 移出远端视口的已登记窗口隐藏并保留代理，再进入时复用；真实成员移除的资源回收仍需单独完成。
- 只有实际位置或大小变化才调用 Windows 窗口布局接口，避免每个视频帧重复调用。
- Hyprland 输出位置使用正确的 `XxY` 表达，并在启动捕获前检查实际物理尺寸和缩放；零尺寸输出不能开始会话。
- 原生移动处理工作区归属后再应用全局坐标。
- 源端输入调度器在连接回收前记录原始错误，避免只留下后续的连接关闭信息。
- 桌面命令由独立工作线程持有控制器与不可变的已提交帧历史，不受视频 owner 的同步工作阻塞；停止信号不会取消正在记账的原生命令。主策略通过阶段栅栏禁止拖动期间维护应用授权，结束后须显式新选择。
- Update 的失败也保留已尝试的原生序号。清理先尝试下一序号；仅在原生端明确拒绝序号时，尝试前一序号，覆盖上次命令未到达的情况。token、身份、原生严格连续序号及同一个清理期限均保留。
- Windows 使用两工作线程运行时和 256 KiB 受限原生管道；Linux 移窗 IPC 去除非必要 fsync，仍核验已连接进程身份及私有文件权限。
