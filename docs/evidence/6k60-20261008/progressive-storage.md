# Progressive pixel storage and leases

Added ProgressiveStorage view over a mapped ProgressiveFrame header plus exact-capacity pixel bank. Writer lease exposes early SHM2 reference, appends bounded pitched rows, release-publishes only committed prefix and marks full completion separately. Unfinished writer destruction aborts. Reader lease exposes only committed bytes, reports completion/cancellation and hides aborted prefixes; its destructor releases reader ownership. Both leases retain a shared mapping owner covering header and pixels even after storage views are destroyed. GPU integration must retain that reader lease until DMA completion, not merely until submission.

Linux optimized and Windows Release tests passed. Small pitched-data test verifies removal of source padding and no unpublished bytes exposed; truncated source input rejected without advancing prefix; all rows written still not complete until finish; busy reader blocks reuse; cancelled writer preserves held slot until release; stale reference rejected. Weak mapping ownership test proves allocation remains alive while a read lease survives both storage views, and is freed after lease release.

Concurrent full6144x3456 test writes128-row bands while reader verifies committed prefixes, checking all84934656bytes against deterministic address-based pattern. This is full CPU-byte integrity in separate producer/consumer views on each OS, not cross-VM BAR or GPU DMA correctness. It uses ordinary memcpy and does not yet include optimized parallel streaming-copy integration.

Not yet bound to production pixel banks or native frame wire. SHM1/SHM2 bank ownership arbitration, mapped header placement, cross-VM full-frame integrity, early wire references, cancellation while DMA active and GPU subrange uploads remain required before enabling progressive payload. Existing normal stream unchanged, no service/plugin restart/input/focus operation. Goal6K60/16.7ms remains unmet; no throughput/latency claim from these tests.
